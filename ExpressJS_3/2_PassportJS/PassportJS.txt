People use Passport.js because it provides a unified, consistent, and modular way to handle authentication, even though things like JWT, 
sessions, and cookies already exist. JWT, sessions, and cookies are methods of storing or transporting authentication data, but Passport 
is an authentication framework that plugs into Express and handles the actual process of verifying a user, integrating strategies like 
local login, OAuth (Google, GitHub), JWT verification, and more. Without Passport, you would need to manually write password verification, 
session handling, OAuth flows, redirect logic, token validation, and route protection. Passport abstracts all that into plug-and-play 
“strategies.” For example, you can swap between local login, Google login, and JWT authentication with minimal code changes because 
Passport standardizes how authentication is done across different methods. In short, Passport isn’t a replacement for JWT or cookies — it 
is the middleware that orchestrates authentication, providing structure, consistency, reusable strategies, and reduced boilerplate for 
real-world apps.
